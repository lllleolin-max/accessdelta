# Internal semantics and tradeoffs

`model.py` validates a closed universe and normalizes all identifier/item orders. Each membership attaches one principal to one role. Each inheritance edge lets its child see its parent's grants. Grants attach to a principal or role and enumerate actions/resources; they represent ALLOW or DENY. Empty action/resource lists match nothing. No conditions are implemented. An absent condition or empty object denotes unconditional grants.

`engine.py` computes one deterministic concrete membership/inheritance path per reachable role with breadth-first traversal. Multiple paths are not enumerated; evidence is one actual path per matched grant, not a completeness claim about paths. Every matching grant is listed. DENY precedence is applied after collecting all relevant evidence. Comparison evaluates both full policies, including pre-existing denies.

`repair.py` enumerates deletion subsets by cardinality, fully evaluates each candidate, and retains every equally least-cost feasible subset. It never assumes access is monotone under deletions. Feasibility means every required request is ALLOW and every forbidden request is DENY in the final model. It says nothing about requests outside these declared lists, though every candidate's complete declared effective set is evaluated. Source model/normalized constraints fingerprints bind application to the intended proposal. `apply` rechecks and yields an immutable new model. CLI output creation uses exclusive creation and never overwrites the input.

`check` validates that the actual repaired JSON equals the proposal's deletions and rechecks finite feasibility; it intentionally makes no optimum assertion. `oracle.py` independently derives transitive role closure by fixed-point Boolean composition, joins membership to that closure, gathers allow/deny effects, and enumerates edit bitmasks. `certify` compares the complete optimum and tied solutions on small instances. It shares schema parsing but no production graph traversal, effective evaluator or subset enumeration.

Let P be principals, R roles, E inheritance/membership edges, G grants, U = P×actions×resources, K editable items and B candidates. Initial evaluator cost is O(U×(E+R+G)); candidate search is O(min(B,2^K)×U×(E+R+G)), plus storage for tied edit subsets. Fixed-point oracle is deliberately small; closure composition can require O(R^5) operations in the simple implementation. The input/candidate caps are work-count limits rather than hard wall-clock guarantees. Finite universes and 20 edits are a strict scope, not a scalable general IAM theorem prover. Large safety-critical migrations need their application-specific authorization engine and real identity inventory.

Full-tie output can approach 2^K when all costs are zero and many subsets are feasible. Deterministic presentation does not assert that only one repair exists. The exhaustive oracle's 12-edit cap makes independent certification an offline small-case tool, not an unrestricted large repair checker.

Threat boundary: model JSON is untrusted, local files are user-selected, and permissions are declarations. No network calls or shell authorization commands occur in the library/CLI. Package/example scripts use subprocess solely to invoke installed local CLI/test/build tools.
