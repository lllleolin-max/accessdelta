# Internal semantics and tradeoffs

`model.py` validates a closed universe and normalizes all identifier/item orders. Each membership attaches one principal to one role. Each inheritance edge lets its child see its parent's grants. Grants attach to a principal or role and enumerate actions/resources; they represent ALLOW or DENY. Empty action/resource lists match nothing. No conditions are implemented. An absent condition or empty object denotes unconditional grants.

`engine.py` computes one deterministic concrete membership/inheritance path per reachable role with breadth-first traversal. Multiple paths are not enumerated; evidence is one actual path per matched grant, not a completeness claim about paths. Every matching grant is listed. DENY precedence is applied after collecting all relevant evidence. Effective-set evaluation traverses once per principal and subtracts aggregated applicable DENY request pairs from ALLOW pairs. Requests outside all ALLOW grants remain default-denied without materialization. Comparison evaluates both full policies, including pre-existing denies.

`repair.py` enumerates deletion subsets by cardinality, fully evaluates each candidate, and retains every equally least-cost feasible subset. It never assumes access is monotone under deletions. Feasibility means every required request is ALLOW and every forbidden request is DENY in the final model. It says nothing about requests outside these declared lists, though every candidate's complete declared effective set is evaluated. Source model/normalized constraints fingerprints bind application to the intended proposal. `apply` rechecks and yields an immutable new model. CLI output creation uses exclusive creation and never overwrites the input.

`check` validates that the actual repaired JSON equals the proposal's deletions and rechecks finite feasibility; it intentionally makes no optimum assertion. `oracle.py` independently derives transitive role closure by fixed-point Boolean composition, joins membership to that closure, gathers allow/deny effects, and enumerates edit bitmasks. `certify` compares the complete optimum and tied solutions on small instances. It shares schema parsing but no production graph traversal, effective evaluator or subset enumeration.

Let P be principals, R roles, E inheritance/membership edges, G grants, U = P×actions×resources, K editable items, B candidates, and H the sum of action×resource pairs over applicable grants per principal. The revised effective-set evaluator costs O(P×(E+R+G+H)); subset search multiplies this by min(B,2^K), with O(U) effective-set memory plus tied subsets. Single-request explanation still costs O(E+R+G). Constraint parsing materializes the universe once, then uses set membership. Fixed-point oracle is deliberately small; closure composition can require O(R^5) operations in the simple implementation. The input/candidate caps are work-count limits rather than hard wall-clock guarantees. Finite universes and 20 edits are a strict scope, not a scalable general IAM theorem prover. Large safety-critical migrations need their application-specific authorization engine and real identity inventory.

CLI parsing rejects duplicate JSON keys instead of accepting last-value-wins authorization fields. Only absent/empty-object conditions are unconditional; false/null/arrays/numbers/strings do not erase restrictions. Input size is 4 MiB, UTF-8 with optional BOM. Invalid proposal shapes, costs, accounting, source bindings and inconsistent status/completeness are rejected before application. The independent checker shares these parser guards, so separate wire probes remain necessary.

The JSON protocol bounds each integer token to 4,300 decimal digits, excluding its sign. Source edit costs share that explicit bound in CLI and SDK. Encoding and parsing use decimal chunks of at most nine digits, retaining exact integer JSON semantics without changing `sys.int_max_str_digits`. Canonical spacing/order and fingerprints match the former JSON representation for admitted values. Over-limit source/fingerprint/serialization requests raise typed `ModelError`; CLI input refusals happen before creation. With at most twenty source costs below 10^4300, any exact subset sum is below 20×10^4300 and therefore has at most 4,302 digits. Unbounded-output SDK proposals keep that arithmetic, as do SDK application, feasibility checks and the small oracle.

Default bounded proposal retention also checks the exact candidate cost against the output-integer budget before attempting wire serialization. A cost beyond it terminates with MAX_INTEGER_DIGITS, UNKNOWN, incomplete ties, lower bound zero and no falsely costed incumbent. Checked may equal candidate_count while the certificate remains incomplete because the result cannot be represented within the protocol. Independent CLI certification that cannot encode its exact oracle result returns typed output-resource UNKNOWN and no certificate; SDK certification still returns its exact dictionary. These are interoperability/resource limits, not mathematical JSON or integer limitations.

CLI wire serialization uses JSON's ASCII escaping for all stdout/stderr reports and help, then writes binary bytes with exactly one LF. This avoids legacy-codec failures and Windows CRLF expansion, while decoding restores exact Unicode values. Model canonicalization and local output-file UTF-8 bytes remain separate from console escaping. `apply` writes compact canonical UTF-8 with no added LF and checks its 4 MiB size before exclusive destination creation. Argument-parser errors are translated into structured INVALID JSON (exit 2); no user encoding environment settings are required. Tests explicitly reset those settings for actual registered-console operations rather than relying on helper capture encoding.

Full-tie output can approach 2^K when all costs are zero and many subsets are feasible. The default proposal budget is 4 MiB of actual ASCII wire bytes, including the single LF. The search computes encoded subset lengths incrementally before retaining each new tied incumbent and reserves incomplete-result metadata conservatively. If a candidate would exceed the budget, it returns UNKNOWN, incomplete ties and the retained feasible incumbent; it does not label a truncated tie list OPTIMAL. A final serialization guard checks the byte accounting. The payload cap bounds retained encoded data, not process RSS or wall-clock time. Explicit SDK `max_report_bytes=None` permits unbounded tie output; the CLI cannot raise its budget above its reader cap. Optional termination metadata is validated while previous proposals without that field remain consumable. Deterministic presentation does not assert that only one repair exists. The exhaustive oracle's 12-edit cap makes independent certification an offline small-case tool, not an unrestricted large repair checker.

Threat boundary: model JSON is untrusted, local files are user-selected, and permissions are declarations. No network calls or shell authorization commands occur in the library/CLI. Package/example scripts use subprocess solely to invoke installed local CLI/test/build tools.
